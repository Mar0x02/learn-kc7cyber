# Daily Challenge - 2026-11-20

**Pertanyaan:** What mount option makes the kernel ignore set-user-ID and set-group-ID bits when executing files from that mount?

**Jawaban:** `nosuid`

**Penjelasan singkat:**
Di Linux ada bit khusus namanya **setuid/setgid** yang bisa di-pasang ke sebuah executable — fungsinya biar pas file itu dijalankan, dia jalan pakai privilege **owner file**-nya, bukan privilege user yang nge-run. Makanya program kayak `passwd` (yang perlu nulis ke `/etc/shadow` punya root) bisa dijalanin user biasa tapi tetep bisa nulis ke file itu.

Masalahnya, kalau ada binary setuid yang "nyelip" di tempat yang gak trusted — misal di flashdisk orang, folder `/tmp`, atau partisi upload — itu bisa disalahgunain buat privilege escalation (jalanin binary jahat yang seolah-olah punya privilege root).

Makanya ada mount option `nosuid` — kalau filesystem di-mount pakai opsi ini, kernel bakal **ngabaikan** bit setuid/setgid di semua executable dari mount itu, jadi mau file-nya punya bit itu kek apa juga, pas dijalanin tetep jalan sebagai user biasa doang. Ini dipakai buat harden mount point yang gak trusted.
